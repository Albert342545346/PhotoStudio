# Фотостудия — КР 1 + КР 2 (один проект)

Информационная система фотостудии: клиенты, фотографы, залы, бронирования фотосессий и платежи.

| Контрольная | Что это | Как запустить |
|---|---|---|
| **КР 1** | консольное приложение (Java + JDBC + PostgreSQL) | `mvn compile exec:java` или `run-console.ps1` / `run-console.sh` |
| **КР 2** | настольное приложение JavaFX (FXML + CSS, TableView, CRUD через диалоги) | `mvn javafx:run` или `run-fx.ps1` / `run-fx.sh` |

Оба приложения — часть **одного Maven-проекта**: они используют одни и те же модель, репозитории (JDBC) и
сервисы бизнес-логики и работают с **одной базой данных PostgreSQL `photostudio`**, созданной в КР 1.
JavaFX подключается к PostgreSQL напрямую через JDBC (как требует задание КР 2), без backend/REST.

Дальше проект расширяется: КР 3 — Spring + REST API, КР 4 — Android (предметная область не меняется).

## Требования

- Java 21, Maven 3.9+
- PostgreSQL 13+ (свой или из `docker-compose.yml`)
- IDE по желанию (IntelliJ IDEA: открыть `pom.xml` как проект)

## Запуск

1. **База данных.** Вариант А — через Docker (из корня проекта):

   ```bash
   docker compose up -d --wait
   ```

   Вариант Б — свой PostgreSQL: `CREATE DATABASE photostudio ENCODING 'UTF8';`

2. **Параметры подключения** — `src/main/resources/database.properties`
   (`db.url`, `db.user`, `db.password`) или переменные окружения `DB_URL`, `DB_USER`, `DB_PASSWORD`.
   Пароль не хранится в Java-коде.

3. **Запуск приложений:**

   ```bash
   mvn javafx:run                  # КР 2: JavaFX
   mvn compile exec:java           # КР 1: консоль
   mvn test                        # unit-тесты
   ```

Если таблиц в базе ещё нет, приложение (любое из двух) само выполнит `sql/schema.sql` и `sql/data.sql`
(создаст таблицы и загрузит тестовые данные). Вручную:
`psql -U postgres -d photostudio -f sql/schema.sql` и затем `-f sql/data.sql`.
Внимание: `schema.sql` пересоздаёт таблицы (DROP + CREATE) — данные удаляются.

Если PostgreSQL недоступен, JavaFX-приложение покажет окно с понятным сообщением, а не stack trace.
Кириллица в Windows-консоли (КР 1): `chcp 65001`.

## Предметная модель (5 сущностей)

| Сущность | Таблица | Назначение |
|---|---|---|
| `Client` | `clients` | клиент (VIP — скидка 10%) |
| `Photographer` | `photographers` | фотограф: специализация, ставка, работает/нет |
| `Hall` | `halls` | зал: вместимость, цена за час |
| **`Booking`** | `bookings` | **основная сущность**: клиент + фотограф + зал + время + статус + цена |
| `Payment` | `payments` | платёж по бронированию |

Связи (FOREIGN KEY): `bookings → clients / photographers / halls`, `payments → bookings`.
ER-диаграмма: `docs/er-diagram.png`. Enum: `BookingStatus` (с допустимыми переходами), `SessionType`,
`PaymentMethod`, `BookingSortField`.

## Архитектура

```
КР 1:  Console UI ─┐
                   ├─► Service ─► Repository (интерфейсы) ─► JDBC-реализации ─► PostgreSQL
КР 2:  FXML (View) ─► Controller ─┘
```

```
src/main/java/ru/mirea/photostudio/
├── Main.java                 КР 1: точка входа консольного приложения
├── AppContext.java           сборка слоёв Repository → Service (общая для КР 1 и КР 2)
├── model/                    сущности, enum, интерфейсы
├── repository/ (+ jdbc/)     доступ к данным: PreparedStatement, try-with-resources
├── service/ (+ pricing/)     бизнес-логика, поиск/фильтры/сортировка, статистика, экспорт
├── exception/                собственные исключения
├── util/                     DatabaseManager, ExcelExporter, TablePrinter
├── ui/                       КР 1: консольные меню
└── fx/                       КР 2: JavaFX
    ├── Launcher.java, PhotostudioFxApplication.java
    ├── controller/           контроллеры вкладок и диалогов
    └── util/                 Dialogs (Alert, FileChooser, модальные окна), FxUtil
src/main/resources/
├── database.properties       параметры подключения
├── fxml/                     main-view, вкладки (bookings/clients/photographers/halls/payments/statistics), формы-диалоги
└── css/styles.css            всё оформление: кнопки, таблицы, формы, ошибки
sql/schema.sql, sql/data.sql  создание БД и тестовые данные
src/test/java/                unit-тесты (JUnit 5, репозитории в памяти)
```

SQL нет ни в консольных меню, ни в контроллерах JavaFX — только в `repository/jdbc` и `util`.

## КР 2: соответствие заданию

| Требование | Реализация |
|---|---|
| Главное окно с основными функциями | `main-view.fxml`: меню + вкладки Бронирования / Клиенты / Фотографы / Залы / Платежи / Статистика |
| `TableView`, понятные заголовки, обновление после изменений | все вкладки; данные перезагружаются после операций и при открытии вкладки; технические поля (ID связей) скрыты — показываются имена |
| Добавление / редактирование / удаление, форма с текущими значениями | модальные формы `*-dialog.fxml`; двойной щелчок по строке — редактирование |
| Подтверждение удаления | `Dialogs.confirm` для всех удалений |
| Связанные сущности — выбор из списков | `ComboBox` клиента, фотографа, зала, типа, времени; `ComboBox` бронирования при платеже |
| Просмотр связанных данных | панель сведений о бронировании + его платежи; у клиента — список его бронирований |
| Валидация до сохранения, понятные сообщения | `FxUtil` (обязательные поля, числа, выбор) + правила сервисов; ошибка выводится красным под формой |
| Поиск по нескольким полям | клиент, фотограф, зал, тип съёмки, комментарий, номер брони (`BookingService.query`) |
| Фильтры ≥ 2 | статус, тип съёмки, период дат (комбинируются) |
| Сортировка ≥ 2 | по дате начала, стоимости, дате создания, имени клиента + направление (`Comparator` в сервисе) |
| Статистика ≥ 5 показателей | 15 показателей, круговая и столбчатая диаграммы, подсчёт за выбранный период |
| Экспорт `.xlsx` / `.csv` через `FileChooser` | кнопка «Экспорт…» (текущий отфильтрованный список) и «Файл → Экспорт всех таблиц» |
| FXML, CSS | интерфейс в `fxml/`, оформление в `css/styles.css` |
| Слои Controller / Service / Repository / Database | см. архитектуру; контроллеры не содержат SQL и бизнес-правил |
| Диалоги вместо консольных сообщений, ошибки без stack trace | `Dialogs`; технические ошибки пишутся в журнал (slf4j), пользователю — короткое сообщение |

## Бизнес-правила бронирования (`BookingService`)

1. Клиент, фотограф и зал должны существовать; фотограф должен работать.
2. Тип съёмки, начало и окончание обязательны; окончание позже начала; съёмка в пределах одних суток.
3. Новое время начала не может быть в прошлом.
4. Студия работает с 09:00 до 21:00.
5. Длительность 1–8 часов, кратна 30 минутам.
6. Участников от 1 до вместимости зала.
7. У фотографа и у зала не может быть пересекающихся активных бронирований.
8. Переходы статусов: `CREATED → CONFIRMED | CANCELLED`, `CONFIRMED → COMPLETED | CANCELLED`.
9. Подтвердить можно только будущее бронирование, завершить — только начавшееся.
10. Завершённое и отменённое бронирование нельзя изменять.
11. Нельзя удалить подтверждённое/завершённое бронирование и бронирование с платежами.

Платежи: бронирование не отменено, сумма > 0 и не больше остатка. Остальные сущности: уникальность
телефона/email/названия, формат телефона и email, ставка > 0, вместимость > 0, нельзя удалить объект,
у которого есть бронирования.

Стоимость: `часы × (ставка + цена зала) × коэффициент типа`, +20% в выходные, −10% VIP
(`StandardPricing → WeekendPricing → VipDiscountPricing`).

## Что показать на защите КР 2

Исходный код и `pom.xml`; БД (`sql/`) и тестовые данные; запуск `mvn javafx:run`; CRUD бронирований и
справочников; поиск, фильтры, сортировку; ошибочный ввод (пустые поля, буквы вместо суммы, занятое время,
вместимость зала); статистику; экспорт в xlsx/csv.

Для демонстрации: бронирование №8 «Подтверждено» и уже прошло — его можно перевести в «Завершено»;
№9–13 — будущие (подтверждение, отмена, конфликты времени, платежи).

Вопросы, на которые стоит уметь ответить: Stage / Scene / Node; как FXML связан с контроллером
(`fx:controller`, `fx:id`, `@FXML`, `onAction="#…"`); почему `ObservableList` обновляет `TableView`;
где бизнес-логика (service), где работа с данными (repository/jdbc); как работает поиск, фильтрация и
сортировка (`BookingService.query`); как обрабатываются исключения (`PhotostudioException` → диалог/сообщение
в форме); как считается статистика и выполняется экспорт (`ExcelExporter`, `FileChooser`).
